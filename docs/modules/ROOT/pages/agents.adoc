= Agents and MCP
:description: The zc-care MCP server, Claude Code plugin, skills and adapters for other agents.

== MCP server

`zc-care mcp` serves these tools over standard input and output:

[cols="1,3"]
|===
| `status` | Live state per target. Read-only.
| `list` | Every declared item with its state, version, newer version and app, then what is installed but not declared. Takes `state` and `kind` filters. Read-only.
| `add` | Declare a package or runtime in one target's manifest now, with its why and section. Takes no config argument; it always edits the default config. Returns `{file,item,section}`. Fails without `section` when the manifest has sections, and names them.
| `remove` | Plan the uninstall of a package and the drop of its manifest line. Changes nothing and returns no plan_id: `{appliable:false, command, plan}`. The user runs `command` at a terminal.
| `capture` | The manifest one target would declare to match this machine. Writes nothing. Read-only.
| `validate` | Check the config offline. Read-only.
| `plan` | Plan and save it. Returns a `plan_id`. Changes nothing.
| `apply` | Apply a saved plan by `plan_id`. Refuses a plan older than 10 minutes, a plan that deletes, overwrites an outside edit or runs a script, and a plan whose live state moved. Ends with a one-line digest.
| `doctor` | Install health, security settings and AI agent configs. Read-only.
| `history` | What was applied, newest first, and from where. Read-only.
| `drift` | What the last daily drift check found. Read-only.
|===

`apply` takes only the id of a plan the server saved, never a plan body. A
plan that deletes is cancelled and the reply names the terminal command for
the user to run.

* *Plans expire.* A saved plan older than 10 minutes is refused, and a
  successful apply spends it. The agent plans again and shows the user the new plan.
* *Every call is logged.* Each tool call, its arguments and whether it worked
  go to `~/.local/state/zc-care/mcp-audit.jsonl`. An apply also lands
  in `zc-care history` as applied from an agent.
* *Tools say what they do.* Each tool carries MCP annotations: read-only
  tools say so, `add` edits a file, `remove` only plans, and `apply`
  changes the machine. A client can ask before the ones that write.
* *Resources.* The server offers the config (`zc-care://config`), the
  last 50 applies (`zc-care://history`) and each target's manifest
  (`zc-care://manifest/<target>`), so an agent reads them without a
  tool call.
* *Prompts.* Each skill is also an MCP prompt, for clients without skills.

== Claude Code plugin

The repository is a plugin marketplace. The plugin lives in `plugin/`: its
`skills/`, `commands/` and `hooks/`, and the MCP server `zc-care mcp`.

[source,console]
----
$ claude plugin marketplace add zoolcoder/zc-care
$ claude plugin install zc-care
----

* `setup` installs the binary, writes a config and runs `doctor`.
* `plan-apply` plans, explains, asks for a yes, and applies that plan by id.
* `add-software` turns "install X" or "I need a tool for Y" into a manifest
  entry: it picks the package, writes it with `add` under a section with a
  why, then plans and applies after a yes. Nothing is installed by hand, so
  the next machine gets it too.
* `review` reads `doctor` and `list`, then reports what is new in the tools
  you rely on, what is broken or drifted, and up to three ideas. It changes
  nothing until you pick.
* Slash commands: `/zc-care:plan`, `/zc-care:apply`,
  `/zc-care:doctor`, `/zc-care:add <tool or need>` and
  `/zc-care:review`.
* The `PreToolUse` hook fails closed. It allows only the read-only
  subcommands (`plan`, `status`, `list`, `history`, `drift`, `capture`,
  `export`, `diff`, `validate`, `doctor`, `version`) in a plain command, and
  asks before everything else: every `apply` (a saved plan file does not
  count, the MCP `apply` with a plan id is the reviewed path), `undo`,
  `upgrade`, `remove`, `init`, `add`, `skip`, `profile`, `mcp`, `-yes` and
  `-fix`, and any `zc-care` command that uses quotes, `$`, backticks, `;` or
  other syntax it cannot read.

== What is new after an update

`review` reports features worth trying in the versions you moved to. It reads
the release notes between the old and the new version, from GitHub releases
when the homepage is on GitHub, and keeps only what touches each item's why.

To know what an update moved, upgrade with `zc-care upgrade`. It
saves the outdated list to `~/.local/state/zc-care/upgrades/`, then
runs `apply -upgrade`; `review` reads the newest file there.

[source,console]
----
$ zc-care upgrade             # everything outdated
$ zc-care upgrade -only brew:tmux
----

== One setup for every agent

The xref:providers.adoc#agents[`agents` provider] writes the same MCP
servers, rules and skills into Claude Code, Codex, Cursor and Gemini CLI, and
pulls the Ollama models you name. A new machine gets them with the rest of
`apply`.

== Other agents

`plugin/adapters/` holds the same rules for Codex, Cursor, Gemini CLI, Copilot and
cloud agents.

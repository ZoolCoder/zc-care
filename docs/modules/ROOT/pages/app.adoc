= ZC Care
:description: ZC Care, the Mac app over zc-care: it picks a new Mac's apps, keeps the setup in place, and cleans, protects and tunes the Mac.

ZC Care is the Mac app over `zc-care`. On a new Mac it picks which
apps to install. It shows what the engine would change, the Mac's vitals and
updates in a menu bar panel, and opens the Care window, which keeps the
setup in place and cleans, protects and tunes the Mac. Each change ZC Care
makes is one you approve first.

It lives in `app/`, a Swift package for macOS 14 and later.

== Install

From the Homebrew tap. The app carries the `zc-care` CLI and the cask
links it onto PATH; ZC Care runs its own copy, so the two always match:

[source,console]
----
$ brew tap zoolcoder/zc-care https://github.com/zoolcoder/zc-care
$ brew trust zoolcoder/zc-care    # newer Homebrew loads a third-party tap only once you trust it
$ brew install --cask zc-care
----

Each release builds ZC Care for Apple silicon and Intel and signs it ad hoc,
not yet with a Developer ID, so macOS blocks the first start: open it once
from the Finder with Control-click, *Open*. `gh attestation verify
ZCCare_<version>.zip --repo zoolcoder/zc-care` checks the zip was built
by the release workflow.

From a clone of the repository:

[source,console]
----
$ make app-install
installed ~/Applications/ZCCare.app; open it once, then tick Open at login
----

`make app` builds `bin/app.noindex/ZCCare.app`, signed ad hoc. `make app-install` copies
it to `~/Applications`. An app opened from the Finder gets no shell
environment, so if `ZC_CARE_CONFIG` is set, `app-install` hands that
path to the app once. *Choose Config…* in the panel changes it later.

== The panel

Click the menu bar mark, or press ⌃⌥Z, to open the panel. It opens on the
Mac page, with the health grade on top as nothing else is. The laptop button
at its foot opens the other pages, *Plan* and *Apply*, and shows a dot when
one of them holds something to do. The arrow beside it reads the Mac again
(⌘R), and its tooltip says how the workstation stands. The sparkle opens
Smart Care. The pages:

[cols="1,3"]
|===
| Page | Shows

| Mac | Disk, memory, CPU, battery, network and sensors, the largest junk folders to free up, and advice. Each tile opens a detail; Disk's shows how fast the drives read and write and lists connected drives, disk images and network shares to eject, Memory's graphs memory used over the last five minutes and splits memory into app, wired, compressed, cached, free and swap, Battery's shows its condition, capacity, cycles, temperature, time left and charger, and CPU's starts with a graph of the load over the last five minutes and the load of each super, performance and efficiency core, then GPU temperature and load, fan speeds and power draw when macmon is installed. Network's shows the connection's service, IP addresses, subnet mask, router, DNS servers and search domains, runs a speed test, and lists your apps listening on a TCP port, marked Network when other devices can try to connect and This Mac when only this Mac can.
| Overview | Each target with what is in place and missing, *Apply* per target, and *All Items*, which opens My Workstation.
| Updates | macOS updates from Software Update, checked every six hours or with *Check Again*, with *Open Software Update*; outdated packages and runtimes, with *Update* per item and *Update All…*.
| Health | `doctor` findings with *Fix*, *Copy Fix* and *Ignore*.
| Services | Homebrew services and launchd agents, with *Start*, *Run Now* and their logs.
|===

The gear opens Settings (⌘,): notifications, the ⌃⌥Z hotkey, the weekly
Smart Care scan, opening at login, Full Disk Access, the config file and
ignored health checks. With notifications on, ZC Care also tells you when an
app dragged to the Trash left more than 1 MB in the Library; the
notification opens Applications' Leftovers on it. Vitals alerts warn of a
nearly full disk, memory pressure, heat, battery wear, a Trash over its
limit (5 GB at first), a Bluetooth device's battery at 20 % and one app
holding a core or 8 GB of memory for ten minutes, each with a limit in Settings. On first launch a Welcome window offers the same
choices; each can be skipped. If SketchyBar is installed, ZC Care hands it the
count of open items for its `zccare` item.

== The Care window

*Smart Care* or *Open ZC Care* in the panel opens a window with one module per job. A
module opens on an intro that says what it does. Its *Scan* reads the Mac;
nothing changes until you press a module's clean or remove button and confirm.

image::care-cleanup.png[ZC Care's Cleanup module, with System Junk and AI Clutter cards]

[cols="1,3"]
|===
| Module | Does

| Smart Care | Scans everything at once and sums it up in cards: junk, clutter, updates and health. *Run* cleans up, then updates.
| Cleanup | Clears caches, logs, build output, npx packages and Mail downloads. Clears *AI clutter*: Claude Code temp files (a folder with a file changed in the last day stays, and so does one with more than 2000 entries, which ZC Care stops reading) and old versions, and the caches and logs of Claude, Cursor, ChatGPT, Windsurf, Codex, Gemini CLI and Chrome DevTools MCP. Empties the Trash.
| Protection | A summary of issues found and checks passed; FileVault, the firewall, System Integrity Protection and automatic security responses beside Gatekeeper's verdict on each app, the apps that run in the background (marked as newly appeared when they showed up in the last seven days), the extensions apps installed (Safari, Share, Finder Sync, Quick Look, Spotlight, Notification Center, Action, Photos and system extensions, with their host app and whether they are on; flagged when the host app is gone or the developer is unidentified; switched in System Settings), the privacy permissions apps hold (each with Reset, through `tccutil`), the Recent Items lists to clear, the known Wi-Fi networks to forget, and each browser's history, cookies, cache, per-site storage and saved tabs, cleared only while that browser is closed; extensions' storage stays.
| Performance | Login items, launch agents and daemons (marked as newly appeared when they showed up in the last seven days), background apps and maintenance tasks: free RAM, flush DNS, thin Time Machine snapshots, reindex Spotlight, verify the startup disk, repair Open With menus, reset Quick Look, clear this user's font caches, and clean Homebrew, Docker and simulators. The top processes by CPU or memory, ten or twenty-five, with *Quit* and *Force Quit* (which asks first); stopped and zombie processes are marked, and ZC Care itself, system daemons and other users' processes cannot be quit.
| Applications | Every app with its size and last use. Uninstalls an app with what it keeps in the Library. *Adopt* replaces an app installed by hand in `/Applications` with its Homebrew cask and declares it. Finds what removed apps left behind. *Updates* lists apps with a newer version: from the app's own Sparkle feed (read only on *Check Now*, https on a public host, at most 5 MB, beta channels skipped; *Open to Update* opens the app, whose own updater installs it), and from Homebrew and the App Store (*Update*). A release that needs a newer macOS is marked. *Intel Only* lists apps whose executable has Intel code and no Apple silicon code: they run only through Rosetta, which Apple is phasing out, so each needs a newer build or a replacement. Apps in `~/Applications` are listed beside `/Applications`; an app installed twice is flagged *Installed Twice*, and uninstalling one copy removes only that copy, since its settings and data are the other's too. Leftovers also lists *Installer Packages*: the receipts `pkgutil` keeps of packages outside Apple's, each with its version, install date and whether its files are still there (*Partly Removed*, *Files Gone*). It changes nothing; `sudo pkgutil --forget <id>` drops a receipt and leaves the files.
| My Clutter | Large files, duplicates, similar images, old downloads and installers. Similar images are photos Vision finds alike; the one with the most pixels stays. Large files filter by kind (videos, music, pictures, archives, installers, documents or other) and by *Not opened for a year*, from Spotlight's last-opened date or, for a file never opened, its last change.
| Space Lens | A map of what fills your home folder. It keeps the scan before the latest, marks folders that grew since, lists the top growers inside the folder you are in with how much each grew, and links a grower to the module that can clean it, such as Cleanup or Developer. *Startup Disk* shows every volume in the startup disk's APFS container, including the hidden System, VM, Preboot and Recovery volumes, the space snapshots and metadata take, purgeable space, local Time Machine snapshots with *Thin…*, and the drive's health from `diskutil`: SMART status, wear, spare blocks, temperature, power-on hours, data written and media errors.
| Cloud Cleanup | Lists the files iCloud Drive keeps downloaded on the Mac, only those iCloud confirms as uploaded. *Remove Download* frees the space; the file stays in iCloud and downloads again when opened. Google Drive, OneDrive and Dropbox are counted but their files are not listed, because their only copy may be on the Mac; open the folder in Finder and use Remove Download there. macOS asks once before ZC Care may read iCloud Drive.
| Developer | Dependencies of projects untouched for 90 days, such as `node_modules` and virtualenvs, and local AI models from Ollama, LM Studio and Hugging Face. Ollama blobs are not offered when any manifest cannot be read. *Docker*, when its CLI is installed and the daemon answers (it always uses this Mac's own daemon and ignores `DOCKER_HOST` and `DOCKER_CONTEXT`): what images, containers, volumes and the build cache take, with *Prune Build Cache* and *Prune Dangling Images*; these delete for good, with no Trash. *Xcode*: DerivedData, Archives, iOS DeviceSupport and the simulators' caches, each with its size and a *Trash* button. *Homebrew*, when `brew` is installed: formulae nothing depends on any more, from `brew autoremove --dry-run`, with *Remove…*; one your config declares is kept, and none is offered when the config cannot be read. What `brew cleanup` would free, with *Clean Up…*, and each `brew doctor` warning, expandable. Reading runs dry runs only, with Homebrew's auto-update off. *Simulator Runtimes*, when `xcrun simctl` lists any: platform, version, build, state and size, with *Delete*, which is permanent; Xcode downloads a runtime again when needed. *Android*, when an SDK is installed: system images and AVDs with their sizes and *Show in Finder*; `sdkmanager` and `avdmanager` remove them.
| My Workstation | What the config declares and what is in place: coverage, each target with its items and *Apply*, the drift check, every item to search, and what was applied, from ZC Care, the terminal or an agent. *Not in Your Config* lists what this Mac has that the config does not name (formulae, casks, App Store apps and runtimes); *Add to Config…* asks for the why line and a section, then runs `zc-care add`, so the next plan shows the item. *Choose Apps…* opens the app picker.
| My Tools | Every tool as a searchable card, including *Screen Cleaning Mode*, which blacks out the screens and locks the keyboard until you click *Done*, hold Esc for two seconds, or sixty seconds pass.
| My Activity | Mac health, disk use, the space ZC Care freed by kind, a tile each for protection, updates, maintenance and the startup drive that opens its view, recommendations from the last scan, and recent activity. *Go* on a recommendation opens the view it names, such as Applications' *Updates* or Space Lens's *Startup Disk*.
|===

== Set Up This Mac

The first time ZC Care runs without a config, it opens *Set Up This Mac*.
*Set Up This Mac…* in the panel, Welcome and Settings opens it again, and so
does `zccare://setup`. It takes four steps:

. *Who it is for*: Everyday, Developer, Creative, or several, and Personal
  or Work. ZC Care writes a starter config to `~/.config/zc-care` with
  `zc-care init`. *Keep the apps this Mac already has* adds them to the
  Brewfile under *From this Mac*. With a config in place, this step only
  saves the Mac's profiles.
. *Make it safe*: the security checks the Mac fails, among them FileVault,
  the firewall, updates, File Sharing, AirDrop and Time Machine. *Fix All as
  Administrator…* first opens a sheet that lists each failing check with the
  exact command that will run as root; *Fix* then runs them all behind one
  password dialog. The rest open their pane in System Settings.
. *Your developer identity*, for a developer Mac: Apple's command line
  tools, git's name and email, and *Set Up in Terminal…*. Terminal makes an
  SSH key behind a passphrase the keychain keeps, signs commits with it,
  signs in to GitHub with `gh` and adds the key there for login and
  signing.
. *Done*: *Choose Apps…* installs the apps, and *Start* runs Smart Care.

Each step after the first has *Back*, and a step that fails to load offers *Try Again*.
Nothing installs until you press *Install* in Choose Apps.

== Choose Apps

The first time ZC Care runs, and whenever you press *Choose Apps…* in My
Workstation or Settings, it lists every package the config declares, under
the Brewfile's sections. At the top you pick who the Mac is for:

* *Everything* ticks every package.
* One profile or several, such as *Developer* and *Creative*, ticks the
  sections tagged for one of them and the sections tagged for no one in
  particular. The Mac's own profiles start selected.

You can untick or tick any package after. *Install* puts what you left out on
this Mac's skip list, takes what you picked again off it, and applies the
rest. Installed packages stay installed. The config does not change, so the
next Mac can pick differently. When the install is done, ZC Care shows the
first keys and commands to try with each app, with a link to its toolbox
page.

The profiles are tags in a section's heading, in brackets:

[source,ruby]
----
# Containers [developer]
brew "colima"   # Docker engine in a light VM
# AI [developer, everyday]
cask "claude"
# Apps
cask "google-chrome"
----

`zc-care skip` lists the skip list; `skip kind:name` adds to it and
`skip -undo kind:name` takes off. `bootstrap.sh` opens the picker on a new
Mac; see xref:new-machine.adoc[].

`zccare://care` opens the window, and `zccare://care/<module>` opens a module
by the start of its name, such as `zccare://care/cleanup`. The scheme is case-insensitive.
`zccare://panel/<tab>` opens a panel tab.

=== What it never touches

* Chats, settings and sessions of AI tools: `~/.claude/projects`,
  `~/.codex/sessions` and the Claude Code version `~/.local/bin/claude`
  runs.
* A Claude Code temp folder used in the last day: a running session owns it.
* Caches of apps that are open.

=== Where it goes

Everything ZC Care removes goes to the Trash by default: junk, caches, browser
data, AI clutter, files, apps, leftovers, dependencies and models. *Put Back*
in My Activity restores an entry and recreates missing parent folders as private (0700). Space frees once the Trash is emptied. To
skip the Trash, turn on *Delete permanently instead of moving to the Trash* in
Settings; then those items are deleted for good. Docker's prune buttons always
delete for good. A Homebrew app is uninstalled through `zc-care remove`,
so it also leaves the Brewfile. Maintenance tasks that need an administrator
ask for your password in a macOS dialog.

ZC Care keeps its last scan in `~/Library/Caches/dev.zoolcoder.zccare` and the
activity log in `~/Library/Application Support/dev.zoolcoder.zccare`, outside
the caches it clears. A corrupt `activity.json` is moved aside as
`activity.json.broken-<unix time>`, so Put Back records survive. If it cannot be
moved, it is kept unchanged and not overwritten.

=== Permissions

Reading the privacy permissions needs Full Disk Access for ZC Care. An ad hoc
signed build is a new app to macOS, so each rebuild asks again. Emptying the
Trash asks once to let ZC Care control the Finder.

== Develop

[source,console]
----
$ make app-test      # swift test, the ZCCareCore tests
$ make app           # bin/app.noindex/ZCCare.app
$ make app-icon      # redraw the icons from app/icon/mark.svg
----

`ZCCareCore` holds the logic, with no UI, and is what the tests cover. `ZCCare`
is the SwiftUI app over it. CI builds and tests both on a macOS runner.

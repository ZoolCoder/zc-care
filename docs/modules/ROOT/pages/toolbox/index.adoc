= The toolbox
:description: Every tool and app the reference workstation installs and configures, what each is for, and the keys that matter.

zc-care does not choose your tools; your config does. This section
describes the setup it was built for: a macOS developer workstation for Go,
Java, Vue and Flutter work with Claude Code at its centre. Each page says what
a tool is for, how the workstation sets it up, and the keys and commands worth
knowing. Take what you like into your own Brewfile.

Every tool here is declared in a Brewfile or `mise.toml` with a comment saying
why it is there, so `zc-care list` shows the same reasons:

[source,console]
----
$ zc-care list -kind cask,brew
----

The colours, terminal, prompt and bar themes live in this repository under
`assets/theme`. The shell, git, app settings and keyboard config live in a
private config repository, applied by the `dotfiles` provider. See
xref:new-machine.adoc[] for that layout.

== How the pieces fit

[listing]
----
Karabiner (Hyper+T)  ->  Ghostty  ->  tmux (dev)  ->  Claude Code | lazygit | zsh
                                                   starship · atuin · fzf · zoxide
SketchyBar  <-  macmon, ZC Care         JankyBorders around the focused window
Raycast     ->  repos, branches, zccare:// URLs
----

A typical start: Hyper+D opens Ghostty running `dev`, you pick a repository,
and tmux opens Claude Code, lazygit and a shell in it. ZC Care in the menu bar
says when packages are outdated or something drifted, and ZC Care keeps the
disk clean. See xref:app.adoc[].

== The menu bar app

ZC Care are part of zc-care itself, not a separate install.
The panel shows the Mac's vitals, the plan, outdated packages, `doctor`
findings and services. ZC Care cleans junk and AI clutter, uninstalls apps
with their leftovers and finds idle dependencies. See xref:app.adoc[].
